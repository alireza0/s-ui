# Добавление и восстановление ноды

В разделе **Ноды** нажмите **Добавить ноду**. Настройки существующей ноды
открываются кнопкой на её карточке. DNS-профили находятся на отдельной вкладке.

| Поле | Что указать |
|---|---|
| Имя в подписках | Название, которое увидит клиент |
| IP сервера | IP адрес VPS |
| Порт и пользователь SSH | Обычно 22 и root; другому пользователю нужен sudo для установки |
| Пароль SSH | Для первоначального подключения или восстановления доступа |
| Шаблоны входящих | Готовые подключения для ноды. Поле можно оставить пустым |

Каждый шаблон описывает один инбаунд. Настройте его во вкладке
**Шаблоны входящих**. Шаблон можно выбрать при установке или назначить
позже из карточки ноды.

В окне существующей ноды выберите нужные шаблоны во вкладке **Входящие**
и нажмите **Применить**. Изменение общего шаблона автоматически
попадает на связанные ноды. Домены, сертификаты, ключи и автоматически выбранные
порты подставляются для каждой ноды отдельно. SSH, домен и восстановление
находятся во вкладке **Сервер**, ход применения — во вкладке **Состояние**.

Для TUIC и Hysteria2 выберите **Автоматический DNS**, профиль и зону. При одном
настроенном профиле значения подставляются автоматически. Включённое поле
**Создать случайный поддомен** выдаёт постоянный адрес вида
`n-<случайное значение>.example.com`. DNS запись должна вести непосредственно на
VPS. Панель выпускает сертификат через DNS-01 и передаёт его агенту; DNS токен
остаётся в панели. Также доступны ручной DNS, предоставленный сертификат и файлы
сертификата на ноде.

Нажмите **Установить ноду**. Панель проверит сервер, все необходимые порты и вход
по своему отдельному SSH-ключу, затем установит службу агента. Пароль используется
только для текущего подключения и не сохраняется. Состояние, этапы и ошибка
операции доступны после открытия карточки ноды; закрытие окна не отменяет задание.
После ошибки используйте **Повторить настройку**.

В карточке клиента выберите ноду целиком. Все её включённые и подтверждённые
подключения попадут в прежнюю подписку клиента. Создание ноды не назначает её
клиентам автоматически. Локальные подключения остаются независимыми.

## Изменение сервера

Откройте ноду → **Доступ к серверу**. Для нового IP укажите доступ к новому VPS.
Для прежнего сервера пароль обычно можно оставить пустым: используется сохранённый
отдельный SSH-ключ.

Перед переключением панель проверяет новый сервер и подтверждает остановку своего
агента на прежнем адресе. Недоступный прежний сервер блокирует перенос; восстановите
его SSH-доступ и повторите операцию. После остановки прежнего агента возможен простой
до готовности нового экземпляра и обновления DNS.

ID ноды и подключений, назначения, клиентские ключи и URL подписки сохраняются.
При управляемом DNS сохраняется домен. Клиентам может потребоваться обновление
подписки, DNS кеша или переподключение.

## После переустановки ОС

Откройте **Восстановить после переустановки**, укажите актуальный SSH-доступ.
Если ключ SSH сервера изменился, отметьте соответствующее поле и введите пароль.
Обычная операция не принимает неожиданный ключ автоматически.

Панель устанавливает агент для существующей ноды. До свежего подтверждения правил
доступа новая установка не запускает VPN по сохранённому старому списку клиентов.
Повторное создание ноды и назначение её клиентам не требуются.

## Резервная копия панели

В окне резервного копирования по умолчанию включена **Полная копия с ключом
восстановления нод**. ZIP содержит SQLite, ключ восстановления при его наличии
и манифест с контрольными суммами. Этот архив содержит приватные данные.
Из полной копии можно исключить статистику и журнал изменений.

Для восстановления загрузите ZIP в то же окно. Неполный архив или неподходящий
ключ отклоняются до замены действующей БД. Отдельный SQLite файл с зашифрованными
данными нод требует соответствующего локального `node-provision.key`.
Импорт исправной копии не блокируется из-за более высоких ревизий действующей
базы или агента. После явного восстановления панель отправляет сохранённые
в копии настройки доступа и сертификатов новыми командами с ревизиями выше
подтверждённых агентом. Защита агента от повторения старых команд сохраняется;
обнулять счётчики, ревизии или регистрацию не требуется. Поддерживаемая старая
версия БД мигрирует штатным механизмом S-UI, в том числе на чистой панели.
При переносе сначала остановите предыдущую панель: одновременно управлять
одними нодами из двух экземпляров не следует.
Новая копия включает последние сохранённые настройки и версии,
даже если их применение ещё ожидается.
После изменения доступа скачайте новую полную копию.

## Границы

Установка агента рассчитана на Linux amd64 или arm64 с работающим systemd
247 или новее. Для первого входа нужен SSH-пользователь `root` или доступ
установщика через `sudo -n`. Установщик использует имеющийся Python 3.7 или
новее. Если его нет, он вызывает APT на Debian, Ubuntu и Armbian либо DNF
или YUM на системах семейства RHEL из списка установщика.

Правила для VPN-портов и HTTP-01 автоматизированы для включённых UFW и
firewalld. Панель изменяет только свои разрешения. Правила внешнего файрвола
провайдера настраиваются отдельно; доступность VPN проверяется клиентом.

Агент содержит ядро sing-box; отдельная служба sing-box не требуется. Установка
nginx, сайта маскировки, внешнего облачного файрвола и Xray/xHTTP в этот сценарий
не входят. Готовность панели подтверждает применение конфигурации; работу из
конкретной сети проверяйте клиентом.
